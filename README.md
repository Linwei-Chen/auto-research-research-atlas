# Auto-Research：从研究代理到自驱实验室

> 一张区分科研闭环深度、证据强弱与真实自主性的可审计研究地图

[在线阅读](https://linwei-chen.github.io/auto-research-research-atlas/) · [综合报告](docs/REPORT.md) · [浏览结构化数据](https://github.com/Linwei-Chen/auto-research-research-atlas/blob/main/atlas.json)

Auto-Research 不是单一产品，而是让人工智能参与问题形成、证据综合、实验执行、结果评价与迭代更新的一组科研工作流。当前最可靠的进展集中在反馈快速、目标可量化的数字环境；开放式创新、长程复现、实体实验安全与独立验证仍明显依赖人类。按路线阅读主贡献，按同心层级判断实际闭环深度，再结合证据等级区分演示、预印本与经同行评议结果。

## 路线导航

| 路线 | 主要关注点 |
|---|---|
| 知识综合与研究构想 | 从论文、知识图谱或结构化证据中发现空白，生成、比较和修订研究问题、假设与方案；不把普通问答或单纯摘要算作科研闭环。 |
| 范式与端到端编排 | 连接构想、计划、执行、分析、写作与评审等多个阶段，研究整体工作流、角色分工、审计轨迹和人机控制点。 |
| 机器学习研发闭环 | 代理修改代码、训练模型、读取量化反馈并保留、回退或组合实验；与预定义搜索空间中的传统 AutoML 以是否存在语义研究决策相区分。 |
| 领域科学发现 | 在生物、医学、化学、材料、社会科学等专业领域调用模型、数据与工具，形成并验证领域假设或候选发现；实体实验可由人类执行。 |
| 实体自驱实验室 | 将研究决策与机器人、仪器和物质世界反馈闭合，覆盖实验选择、执行、表征与后续更新；人工搬运或关键判断必须明确披露。 |
| 评测、复现与治理 | 用基准、复现、外部审计、风险分析和安全控制验证研究代理的能力边界，特别关注泄漏、长程失败、同质化和现实危害。 |

## 如何阅读

1. 打开[在线地图](https://linwei-chen.github.io/auto-research-research-atlas/)，先从“路线 × 层级”总览判断领域结构。
2. 用关键词和出版状态缩小范围，再点击聚合节点比较同一分支中的工作。
3. 进入详情页，按“问题—机制—证据—局限—启示—来源”下钻到单项工作。
4. 需要完整论证时，继续阅读[综合报告](docs/REPORT.md)与[检索与证据审计](docs/SEARCH_AUDIT.md)；需要二次分析时使用 `data/` 导出。

页面不依赖服务端。克隆仓库后可直接双击 `index.html` 离线阅读；论文原文、代码和数据集等外部链接需要联网。

## 研究范围与证据边界

覆盖奠基工作至 2026-08-09 的英文与中文可核验来源；核心对象必须跨越至少两个实质科研环节并产出可检查结果，另纳入定义路线、评测失败或治理边界的关键工作；普通搜索写作工具、传统 AutoML 和纯营销项目排除。

地图把出版状态、阅读优先级、证据质量和展示层级分别记录，避免把“已发表”“重要”“证据强”或“工程成熟”混为一谈。详情页中的机制图是依据文字证据绘制的解释性示意，不替代原论文图表或独立复核。

## 项目文件

- `index.html`：交互式研究全景、路线说明、时间线与完整索引。
- `paper.html?id=...`：每项工作的机制、证据、局限和一手来源详情。
- `atlas.json`：人工维护的结构化研究真源。
- `docs/REPORT.md`：领域综述、关键分歧、时间线与开放问题。
- `docs/SEARCH_AUDIT.md`：检索范围、纳排规则、覆盖限制和反证记录。
- `data/papers.json`、`data/papers.csv`、`data/references.bib`：便于阅读、分析与引用的导出。
- `planning/` 中公开的账本文件：范围合同、查询、筛选和核心主张的可追溯记录。

## 数据更新与复核

网页和数据导出由 [`build-research-atlas`](https://github.com/Linwei-Chen/build-research-atlas) 从 `atlas.json` 确定性生成。更新记录后，应重新编译并执行严格验证与真实浏览器回归；不要直接改写 `data/` 中的派生文件。

这是一份有明确截止日期和纳入边界的研究综述，不声称覆盖互联网上的全部长尾资料。若发现题名、状态、链接或证据表述需要修正，欢迎在仓库中提交问题并附一手来源。
